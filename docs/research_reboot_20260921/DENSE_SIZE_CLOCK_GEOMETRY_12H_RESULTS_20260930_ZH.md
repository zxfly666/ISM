# Dense尺寸覆盖 × 时间输入：预检结果与预算停止报告

日期：2026-09-30，时间为UTC+8。研究标识：`dense_size_clock_geometry_12h_20260930`。

## 结论先行

**实现、数学/软件检查和小样本可学习性测试通过；12小时启动预算门未通过，所以正式四组实验没有启动。** 这不是一次“模型又没改善”的科学结果：本轮没有24个正式模型、20×20留出预测或D−A主比较，不能据此评价跨尺寸泛化成败或否定老师idea。

实测完整更新均值为0.108157秒。按此均值，57.6万次更新仅训练约17.305小时；按事先约定的慢重复和1.35安全系数，再计评估、审计、备份及余量，全流程保守投影26.486小时，超过12小时硬上限。此前8.5小时训练、12小时总计只是**未测速的资源规划**；这次实测不支持该规划。停止正式启动是方案预先规定的行为，不是根据效果挑选性停止。

## 1. 本轮本来要检验什么

保持同一个dense网络，以2×2配对对照区分训练尺寸覆盖和时间输入：

| 臂 | K4/G8训练容器边长 | 时间输入 |
|---|---|---|
| A | 4、6 | 自然遮盖比例`1−K/N_valid` |
| B | 4、6 | 从训练起固定0.75 |
| C | 4、6、8、12 | 自然遮盖比例 |
| D | 4、6、8、12 | 从训练起固定0.75 |

六个新seed、每seed四臂同初始化/物理样本/标签配对，共24模型，每模型24k更新。主权重固定final raw；EMA和8k/16k只作次要诊断。唯一主终点为20×20中心容器上的G8留出模式条件KL，比较D−A；还必须分别满足绝对误差和旧任务保留门。没有MC和大图生成。

老师思路在本轮中的对应是：**先保持dense，在训练时覆盖不同block size，并检查条件网络是否真的使用相对几何。** 固定时间输入是依据既有失败提出的额外对照，不冒称老师原话。本轮即便正式通过，也只验证精确局部条件任务，不覆盖真实物理间距变化、长程边缘条件、多温度或完整联合生成。

G8的隐藏2×2腔体被八个已观测邻居包围；真值由16种隐藏状态精确求和。两个同为4正4负的边界排列，可产生约0.18573和0.81427的不同目标概率，因而单纯计数不足以完成任务。D4和整体翻转的所有副本分到同一个组；72组固定拆为48训练、12验证、12测试，避免对称副本跨拆分泄漏。预检的可学习性测试只用其中64条训练记录，没有查看留出模型表现。

## 3. 已完成的检查与真实结果

七项数据/数学单测通过，包括精确枚举、非计数见证、拆分隔离、query隐藏、K1不错误扩域、配对和指标。GPU上保存/恢复后的下一更新，raw、EMA、AdamW与连续执行逐字节一致。PAD前后梯度最大差`2.98023e−8`、参数差`1.13687e−13`，invalid PAD嵌入梯度为0；平移、联合重排及PAD概率差均小于`3.5e−12`。

第一次GPU软件检查曾因AdamW计数张量的CPU/CUDA位置不一致报错。冻结前修正为先在CPU加载存储，再由模型和优化器按自身设备策略恢复；不是跳过比较或放宽容差。原始代码副本和失败记录保留。该错误发生在可学习性测试之前；后续两种策略的可学习性测试均只执行一次，原12小时时钟未重置。

两个同初始参数的scratch模型，在固定64条G8训练记录、4×4容器上各训练2048步，全batch软标签CE；128步warmup，峰值/终值学习率同方案。预设准入门为max KL≤0.02且max概率误差≤0.10。

| scratch策略 | mean KL | max KL | max概率误差 | 准入门 |
|---|---:|---:|---:|---|
| native | 7.17861e−8 | 5.32679e−7 | 0.0005118985 | 通过 |
| canonical | 3.03526e−7 | 1.63225e−6 | 0.0008958547 | 通过 |

这支持“该实现能拟合这批精确训练例”，**不支持**“已经跨尺寸泛化”“D优于A”或“老师idea已验证”。scratch的A/B标签仅表示两种clock，不是已完成六seed正式A/B臂。保存的概率/logits和目标可以独立重算KL，CE与真值熵分列。

## 4. 为什么没有正式启动

四臂×四周期，每类预热8步、三次各32步，含真实两微批、反向、AdamW、EMA、输入hash及日志。所有48次测量均保留，并另测1000步完整块及真实检查点I/O。

| 量 | 实测或投影 | 性质 |
|---|---:|---|
| 48次测量的平均更新耗时 | 0.108157190秒 | 实测 |
| 单次测量均值范围 | 约0.1044–0.1181秒/更新 | 实测 |
| 1000步完整块 | 108.766528秒 | 实测 |
| 57.6万更新按均值外推 | 17.305小时 | 不含安全余量的训练投影 |
| 训练保守投影 | 23.990小时 | 每类最慢重复×1.35及检查点I/O |
| 3240份预测及控制评估 | 847.102秒 | 预检形状测速投影 |
| 全流程保守投影 | 26.486小时 | 含已耗时、审计、备份、余量 |
| 用户硬预算 | 12小时 | 不延长、不重置 |
| 远端可用/含底线需求 | 16.430 / 8.601GiB | 空间门通过 |

统计审计1800秒、备份2700秒、额外余量2700秒仍是预留，不冒称已完成正式大包传输测速。即使不计这三项，训练自身也超过12小时；不能靠“少留点备份时间”解决。

GPU峰值已分配约0.80GiB，预检某些时刻GPU利用率约12%。这提示有必要剖析吞吐瓶颈，但瞬时利用率**不能单独证明**瓶颈就是Python、优化器或GPU算力中的哪一个，更不证明一定能加速到12小时内。
